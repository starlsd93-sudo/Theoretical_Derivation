# R5 推导交付包：schema + 自检

> 交付包是本 skill 与下游（写作、报告、代码实现、设计评审）之间的接口。**字段语义稳定，承载形态可演进**：下游依赖字段含义，不依赖文件形态。
> 文件名：`[R5]<任务>_交付包_vN.md`（多端整合版加 `_整合版`），输出至 `<root>/output/`。

## 格式

- UTF-8 Markdown；公式 LaTeX（行内 `$...$`，行间 `$$...$$`），不用 MathML/OMML。
- 图表只给占位描述，不画图。
- 引用须可溯源；缺字段写 `［待补：字段名］`，不猜测。
- 篇幅建议：总长 ≤ 8000 字；每个推导步骤 ≤ 200 字（不含公式）；每个公式注释 1–3 行。

## 自检清单（不合格不交付）

| # | 项 | 通过标准 |
|:-:|:--|:--|
| 1 | 输入齐备 | R0、R1、R4 报告必有；标准/严格模式另需 R2；R3 可融入 R2 但决策须留痕 |
| 2 | 公式 | 全 LaTeX，无 OMML/MathML |
| 3 | 引用 | 全部可溯源，缺字段占位，无猜测 |
| 4 | 假设 | §3 编号完整，§4 前置条件均可在 §3 找到 |
| 5 | 有效域 | §7.4 三项齐全 |
| 6 | 验证 | §7.1 覆盖所选模式要求的全部判据，含外部锚点 |
| 7 | 非阻断观察 | R4 报告 §3 全部条目进入 §7.2 |
| 8 | 闸门 | §7.6 四问全通过 |
| 9 | 篇幅 | 每步骤 ≤ 200 字；总长超限时先压 §5，再压 §6 |
| 10 | 无新增推导 | 交付包中每个结论都能在 R0–R4 中找到出处 |

**常见情形**：R4 修订建议非空 → 先回退修订并重跑 R4，再做 R5。R4 部分通过 → §7.1 分类标注，§7.2 写明原因与边界。
