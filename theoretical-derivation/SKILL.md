# theoretical-derivation：理论推导与多方验证工作流

## 0. 一句话定位

把一个开放的建模/推导问题，经**六步骨架**收敛为可复现、经多方验证的推导结论。不依赖任何单次推理的正确性，而靠**结构假设由人钉死 + 双路独立推导 + 对比选定 + 对独立外部锚点的数值验证 + 关键节点人工审阅**把错误率压到可接受范围。

本 skill 只管"推得对、验得实"。上游的文献整理、下游的成文润色与排版不在范围内；R5 交付包是给下游（写作、报告、代码实现）使用的结构化接口。

## 1. 工作目录约定

工作根目录由用户指定（下称 `<root>`）。启动前确认输入齐备，**缺则提示用户补充，不臆造、不跳过**：

| 位置 | 内容 | 必需 |
|:--|:--|:--:|
| `<root>/inputs/` | 问题背景、已知参数、已有推导、记号与约定文件（若项目有统一符号表/约定，放这里并在 R0 引用）| 是 |
| `<root>/inputs/refs/` | R2 所需教材段落与参考文献（优先 markdown 文本）| R2 需要 |
| `<root>/work/<任务名>/` | R0–R4 中间产物；多端并行时建子文件夹 `A/`、`B/`、`C/` | — |
| `<root>/output/` | R5 推导交付包 | — |

**文件命名**：`[R0]<任务名>_问题陈述_vN.md`、`[R1]…_推导A_vN.md`、`[R2]…_推导B_vN.md`、`[R3]…_选定_vN.md`、`[R4]…_verify_vN.py`、`[R4]…_验证报告_vN.md`、`[R5]…_交付包_vN.md`。外部 AI 产物加前缀 `[C-<模型名>]`。

## 2. 六步骨架

```
R0 问题数学化 ─N0─► R1 独立推导 ──┐
                                  ├─► R3 对比选定 ─N3─► R3.5 参数冻结 ─► R4 全程数值验证 ─N4─► R5 交付包
                   R2 文献借鉴推导 ┘
```

| 阶段 | 产出 | 节点 | 挂载规则 | 推荐模型档 |
|:--:|:--|:--:|:--|:--:|
| **R0** 问题数学化 | 问题陈述 + 分解计划 + 验证判据 | **N0 必审** | **P1 结构假设钉死** | 强推理 |
| **R1** 独立推导 | 推导 A + 四项自查 | 可选 | **P2 完整通解 + P3 前提显式** | 强推理 |
| **R2** 文献借鉴推导 | 推导 B + 教材对照 + R1 补强 | 可选 | 文献真实性核查；推导段同挂 P2/P3 | 执行（推导段用强推理）|
| **R3** 对比选定 | 选定推导 + 依据 + 有效域 | **N3 必审** | **P4 有效域三问** | 强推理 |
| **R3.5** 参数冻结 | 参数冻结表 | 轻量 | 数值真值钉死、跨端统一 | — |
| **R4** 全程数值验证 | 脚本 + 验证报告 | **N4 必审** | **五类判据 + 四问闸门** | 强推理主导 / 核验档代入 |
| **R5** 交付包 | 推导交付包 | 简审 | 交付包 schema | 执行 |

- **建模的主战场在 R0 与 R3**：R0 决定"解的是不是对的问题"，R3 决定"这个模型在哪里失效"。规则见 `references/modeling.md`。
- **双路（R1/R2）是正确性主力机制**：R1 不看外部文献独立推（防锚定），R2 对照教材/文献推并补强 R1；R3 对比，分歧即风险点。
- **R4 是错误拦截的最后防线**：形式自洽但物理错误的推导（力臂取错、符号反号），只有对独立外部锚点做机器精度对照才能暴露。
- 各阶段详规与失败回退见 `references/workflow.md`。

## 3. 工作模式（R0 后推荐，用户确认或覆盖）

| 模式 | 流程 | 适用 |
|:--|:--|:--|
| **轻量** | R0 → R1 + 四项自查 → R4 精简（判据 1/2/3）| 探索性、短推导、有教材答案的问题 |
| **标准**（默认）| 完整 R0→R5 | 正式建模、要交付他人使用的结论 |
| **严格** | 标准 + 跨会话/跨模型独立复算（§4 三角）+ 验证 harness H2/H3 | 核心结论、将发表或用于设计决策的结果 |
| **审校** | 对已有推导跑 P1–P4 + 四问闸门 + R4 判据，输出问题清单与修正 | 审他人或自己的既有推导 |

推荐规则：结论被下游依赖越深、越缺现成闭式解、越是新颖代数结构 → 档位越高。R0 结束时输出一句「推荐 <模式>，理由 = …；确认或覆盖？」。

**执行环境**（与模式正交，同一任务不同阶段可换）：

| 环境 | 位置 | 特点 |
|:--:|:--|:--|
| **A** | Claude Code 等有本地 Python 的环境 | 推-验一体，R4 必须在 A 跑实；主推 + 终裁端 |
| **B** | 网页对话（无本地 Python）| 文献对标、长链概念推理；R4 产出验证指令交 A 跑；同会话上文可能污染，不作独立第一意见 |
| **C** | 任一外部 AI | 物理隔离的独立第二意见；Claude 只生成一份自包含委派提示词（`references/prompts.md` §F）|

## 4. 多方验证（核心）

多方验证分三层，层层独立：

1. **推导层**：R1 独立推导 vs R2 文献推导，R3 对比（同会话内的路径多样性）。
2. **数值层**：R4 五类判据，其中 ★ 独立外部锚点（闭式解 / 第二推导 / 特例退化）与 ★ 标准库实跑为强制项（`references/verification.md`）。
3. **执行端层**：严格模式下的三角——A 主推终裁 + C 外部 AI 独立复算 + B 文献对标；或冷启动新会话 / subagent 独立复算。**价值在"独立端一致"，与哪端更强无关**；同模型的多会话只提供上下文多样性，不替代跨模型复算（`references/cross-validation.md`）。

分歧处置顺序：**先排除口径差**（参数取值、约定、简化假设），**再判推导错误**，数值终值取经最强验证的端。

## 5. 严谨性规则（必读）

| 规则 | 阶段 | 强制动作 | 拦截的失误 |
|:--:|:--:|:--|:--|
| **P1** | R0（R2 复查）| 结构假设钉死，缺项必问 | 模型把缺失结构补成最规则情形 |
| **P2** | R1/R2 | 完整通解次序，不因预判省略中间项 | 抄近路、破坏可复现次序 |
| **P3** | R1/R2 | 隐含前提显式化（每个计数/取值说来源）| 给数不说依据，逻辑缺口 |
| **P4** | R3 | 有效域三问（前提 / 失效条件 / 推广路径）| 解出即默认模型成立 |
| **闸门** | R4 收尾 | P1–P4 四问逐条过，任一否则退回 | 形式走完、实质没做 |

> 心法：严谨 ≠ 话多；建模能力高低在"知不知道模型何时失效"，不在"解没解出来"；结构假设必须由人钉死。全文与反例见 `references/modeling.md`（唯一来源）。

## 6. 模型路由

> 口诀：**推错会让后续返工的 → 强推理档（如 Opus）；框架已定只是执行的 → 执行档（如 Sonnet）；有标准答案能机械核验的 → 核验档（如 Haiku）。**

开放建模（需自设假设、无唯一解）用强推理档 + 高思考预算，并注入 P4 三问提示词（`references/prompts.md` §C）。每个任务启动时提示当前阶段推荐模型，由用户确认或覆盖；实际所用模型记入交付包头部。

## 7. 输出与记号

- 过程文档与交付包均用 `.md`；公式用 LaTeX（KaTeX 兼容）：行内 `$...$`，行间 `$$...$$`。
- 记号与约定以项目约定文件为准；无约定文件时 R0 §2 当场锁定（符号、单位制、参考系、参数化、正负号/扰动侧等），后续阶段不得改选。
- 引用须可溯源，**禁止编造文献、章节号、卷期页**；缺字段用 `［待补：字段名］` 占位。

## 9. 启动一个推导任务

1. 确认 `<root>` 与输入齐备（§1）；选执行环境（§3）。
2. 跑 R0（`references/modeling.md` §1），N0 审阅时一并确定**工作模式**与 **harness 档位**。
3. 按模式推进 R1→R4；严格模式按 §4 启动跨端复算。
4. R4 过五类判据 + 四问闸门，N4 通过后进 R5。
5. R5 按 `templates/derivation-package.md` 封装至 `<root>/output/`。

审校模式直接从 `references/prompts.md` §D 开始。
